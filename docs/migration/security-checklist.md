## Known limits (accepted for now)

- **Inline scripts are allowed** (`script-src 'self' 'unsafe-inline'`). Next.js streams page data in inline scripts; the alternative, per-request nonces, forces every page to render dynamically and is incompatible with Cache Components' static shells (fix 20). The app renders no user-supplied HTML: the only `dangerouslySetInnerHTML` is JSON-LD with `<`, `>`, `&`, `'` escaped (`components/public/breadcrumb.tsx`). Revisit if user-generated rich text is ever added.
- **`/api/v1` content edits are eventually consistent for a few milliseconds**: Next.js applies a route handler's cache-tag expiry after the response is sent. The CMS forms (Server Actions, `updateTag`) are read-your-own-writes.
- **SRI is experimental and partial**: framework chunks are hashed; some per-page chunks are not yet. It is defence in depth, not the main control.
- Better Auth's own warnings ("Invalid password") are logged by the library without credentials.

## Manual check, 2026-10-24 (local production build)

`curl -si -X POST /api/v1/attempts/start` → `Set-Cookie: mce_guest=…; Path=/; HttpOnly; SameSite=lax` (no `Secure` on plain-http localhost, as intended).
